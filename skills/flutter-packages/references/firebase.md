# Firebase (FlutterFire)

- Initialize once in `main()` before `runApp`:
  `WidgetsFlutterBinding.ensureInitialized(); await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);`
  — use whatever the project already does (some use native config files without `firebase_options.dart`).
- Config files (`google-services.json`, `GoogleService-Info.plist`, `firebase_options.dart`) are generated by
  `flutterfire configure` — don't hand-write or invent their contents. If flavors exist, each flavor has its own.
- Keep all `firebase_*` packages on compatible versions (same BoM generation). Add new ones with `flutter pub add`
  so the resolver picks compatible versions; don't pin one package to a far-off major.

## firebase_messaging
- iOS: push capability + background modes (remote-notification) + APNs key in Firebase console; call
  `requestPermission()`.
- Android 13+: `POST_NOTIFICATIONS` runtime permission.
- Background handler: top-level (or static) function annotated `@pragma('vm:entry-point')`, registered with
  `FirebaseMessaging.onBackgroundMessage` before `runApp`. It runs in a separate isolate — no access to app state/DI.
- Foreground notifications on Android are not shown automatically — the project likely uses
  `flutter_local_notifications` for that; reuse its existing channel setup.
- Handle all three entry points: `getInitialMessage()` (terminated), `onMessageOpenedApp` (background), `onMessage` (foreground).
- Token: `getToken()` + `onTokenRefresh` → send to backend the way the project already does.

## firebase_crashlytics
- `FlutterError.onError = FirebaseCrashlytics.instance.recordFlutterFatalError;` and
  `PlatformDispatcher.instance.onError` for async errors — usually already in `main.dart`; don't duplicate.
- Don't send personal data in custom keys/logs.

## firebase_remote_config
- Set defaults (`setDefaults`) and `setConfigSettings` (fetch timeout / minimum interval) before `fetchAndActivate`.
- Read through the project's wrapper; never block app start indefinitely on a fetch.
